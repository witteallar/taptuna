# AGENTS.md

Файл-инструкция для ИИ-агентов (Pi, Claude Code, Cursor и др.), работающих над проектом «Лаборатория протоколов». Читается агентом при старте сессии. Источник истины — `ТЗ.md` (v3.0 final). При расхождении приоритет у `ТЗ.md`.

---

## 1. Что это за проект

Офлайн-инструмент для исследования недокументированного бинарного обмена поверх TCP/IPv4 по записям PCAP/PCAPNG. Инженер открывает запись, восстанавливает прикладной поток, формулирует и проверяет гипотезы о структуре сообщений, находит контрпримеры, сохраняет и переносит исследование, экспортирует читаемый отчёт и машиночитаемую интерпретацию.

**Один пользователь, один ПК, браузер = GUI.** Всё взаимодействие — через веб-интерфейс на `127.0.0.1:5000`. Сеть в рантайме не нужна. Консоль — для запуска CLI и `taptuna serve`.

## 3. Глоссарий (обязателен в коде, БД, UI)

Термины — контракт. Не синонимизировать, не переименовывать.

| Термин | Значение |
|---|---|
| Запись трафика | Исходный PCAP/PCAPNG, **read-only**, sha256 |
| Сессия | Экземпляр TCP-соединения (5-tuple). Реюз портов не сливает |
| Направленный поток | Байты одного направления, восстановленные по seq |
| Фрейминг | Выделение прикладных сообщений из потока. Граница TCP-пакета ≠ граница сообщения |
| Интерпретация | Правило/модель/скрипт, извлекающий структуру/значения |
| Гипотеза | Предположение о структуре/назначении, связанное с наблюдениями и основаниями |
| Корпус | Выбранный набор записей/сессий для проверки |
| Контрпример | Данные, где правило не выполняется |
| Observation | То, что видно в байтах |
| Rule | То, что извлекла интерпретация |
| Hypothesis | Предположение о смысле |
| Action Log | Хронология действий над устройством с параметрами и наблюдаемым результатом |

Имена в коде — английские (`Session`, `DirectionalStream`, `Observation`, `Rule`, `Hypothesis`, `ActionLog`, `Corpus`, `Counterexample`, `Ambiguity`, `Gap`). В UI — русские термины.

## 4. Границы v1

### In scope
- Ethernet + IPv4 + TCP, офлайн.
- PCAP и PCAPNG (single-section, single-interface).
- Одна точка захвата, без IP-фрагментации.

### Out of scope (жёстко)
- IPv6, UDP, SCTP, ICMP.
- Multi-interface / multi-section PCAPNG → `ERR_MULTI_INTERFACE`.
- Live capture.
- Расшифровка трафика, разбор сжатия.
- Восстановление полного автомата состояний.
- Incremental ingest.
- Сравнение двух PCAP.
- Распознавание протоколов поверх TCP.
- Распределённая работа.
- Архивный формат проекта (только **каталог**; архивируется внешним инструментом).
- Экспорт вне Markdown / HTML / JSON.

Задачи из списка «возможные расширения» (объяснимые предложения закономерностей, авто-связывание запрос↔ответ, сравнение между записями, контролируемые эксперименты) — **стоп и вопрос пользователю**. В v1 не делаем.

## 5. Инварианты (проверяются тестами, не обсуждаются)

- **I1.** Исходный PCAP read-only, идентифицируется по sha256.
- **I2.** Любой результат ссылается на `(source_id, byte_range)`.
- **I3.** `known` / `unknown` / `ambiguous` различимы в модели, API, UI.
- **I4.** Observation ≠ Rule ≠ Hypothesis — три таблицы, разные API.
- **I5.** Смена правил не переодевает старые результаты; stale вычисляется при чтении и никогда не удаляет старые прогоны.
- **I6.** Долгие операции — jobs с SSE-прогрессом и отменой. tshark: `terminate()` → 5 с → `kill()`. Sandbox: `kill()` + пометка мёртв.
- **I7.** Проект переносим: относительные пути везде, включая ref-режим (относительно `TAPTUNA_REF_ROOT`).
- **I8.** Детерминизм. Одинаковый вход + версия интерпретации + seed → байт-в-байт одинаковый `result_hash`. Reassembly детерминирован по `(abs_seq, frame_number)`.

**Дополнительные запреты из §6.2 ТЗ:**
- `shell=True` — нет.
- `-Y tcp.stream==N` отдельным вызовом на каждую сессию — нет.
- `-T json` на весь файл ради списка сессий — нет.
- `follow,tcp,raw` как источник прикладного потока — нет.
- tshark на каждое действие UI (кроме point-lookup одного frame) — нет.
- Парсинг `tcp.flags` как hex/dec — нет; SYN/ACK/FIN/RST отдельными полями.
- Абсолютные пути к tshark внутри проекта — нет.
- `RLIMIT_NPROC` в sandbox — **не трогать**.
- Zero-fill для пропусков — нет.
- Переиспользование sandbox-worker после таймаута — нет.

## 6. Ключевые технические контракты

### 6.1. Ingest — ровно один вызов tshark на файл

Точная команда — в §6.2 ТЗ. Список сессий формируется из тех же строк (группировка по `tcp.stream`). `ip.defragment:FALSE` — вход без фрагментации. При встрече фрагмента — предупреждение в лог, склейки нет.

Тест с fake-tshark **считает** запуски: должен быть ровно один на файл.

### 6.2. Reassembly
- Опорная точка — **максимальный непрерывный** seq, не последний увиденный.
- Сортировка по `(abs_seq, frame_number)` — обязательно.
- Одинаковые ретрансмиссии — дедуплицировать, исходные пакеты сохранить.
- Различающиеся перекрытия → `Ambiguity` + политика `first_wins | last_wins | halt_and_mark` (default `first_wins`, в манифесте и per-direction).
- Пропуск/усечение → `Gap`, байты `unknown`, zero-fill запрещён.
- `tcp.len == 0` не создаёт сегмент.
- Отсутствие SYN → `roles_established = false`.
- Wraparound seq — RFC 9293, окно ±2^31.
- Одна система координат: `byte_map` — offsets относительно `stream_start`; `abs_seq` — внутренняя деталь.

### 6.3. Интерпретации
- YAML/JSON, `schema_version: 1`. Ровно один из: declarative | script (`decode(msg, ctx)`).
- Framing: `length_prefix | delimiter | fixed | regex`. Валидация: `header_size ≥ offset + size`; `value ∈ {payload, total}`; `max_message` обязателен.
- Типы полей: `u8/i8/u16be/u16le/i16le/.../u64le/i64le/bytes/ascii/utf8/ipv4/mac/bcd`.
- Выражения `offset`/`size` — AST-whitelist, имена `len/header_size/max_message`, арифметика `+ - * / // %`. `size: remaining`.
- Оба движка возвращают per message: `{index, stream_offset, length, message_name, status, fields, notes, unknown_ranges}`. `status ∈ ok | partial | no_match | unknown_frame`.
- Versions immutable. `parent_id` для происхождения.
- Stale вычисляется при чтении; старые прогоны не удаляются.

### 6.4. Sandbox script
- Отдельный процесс, **один долгоживущий worker на job** (не на direction).
- `RLIMIT_CPU`, `RLIMIT_AS` (default 512 MiB), `RLIMIT_FSIZE=0`. **`RLIMIT_NPROC` не трогать.**
- Import whitelist: `math`, `struct`, `binascii`, `re`, `dataclasses`, `typing`, `collections`, `json`, `decimal`, `fractions`, `enum`, `itertools`, `functools`, `operator`, `string`, `textwrap`.
- `random` — детерминирован с seed.
- `stderr` вычитывается родителем всегда.
- Таймаут → `kill()` + respawn + пометка клиента «мёртв». Не переиспользовать.

### 6.5. Классификация сообщения (§9.2 ТЗ)

Приоритет вердикта: `violation > ambiguous > incomplete > ok > not_applicable`.

### 6.6. Нативное ядро (§12 ТЗ)

В Rust: reassembly, framing, декларативный экстрактор, safe-eval.
В Python: subprocess tshark и парсинг строк, SQLite/store, Flask, jobs/SSE, sandbox, отчёты, action_log.
Fallback — Python-реализация под `TAPTUNA_NATIVE=0`. Тесты на обоих движках, `result_hash` байт-идентичен.

### 6.7. Wire-парсер в Rust (§12.5 ТЗ)
- Поддержка одного VLAN-тега (802.1Q, 802.1ad).
- IP-фрагменты → отказ с предупреждением, не склейка.
- Проверка `IHL ≥ 5`, `data_offset ≥ 5`, `total_len ≥ ip_hdr_len`.
- Обрезка по `ip.total_len` (отсечь padding).
- `Ok(None)` — не-IPv4/не-TCP (не ошибка). `Err` — распознан, но повреждён.

### 6.8. SQLite (§14 ТЗ)
- `PRAGMA user_version` + мигратор. `schema_version` как поле в JSON — **не использовать**, только `user_version`.
- Индексы: `vres(run_id, status)`, `vres(run_id, id)`, `sessions(capture_id, stream_index)`, `interp(name, version DESC)`, `seg_dir_offset`, `obs(target_type, target_id)`.
- Payload > 4 КиБ — в CAS (`blobs/<sha256>.bin`), inline ≤ 4 КиБ.
- `directions.gaps_json`, `directions.ambiguities_json` — JSON-столбцы.
- Stale: superseded by `name@N+1` или drift политик (snapshot в `params_json`).

## 7. Соглашения по коду

### Python
- Python 3.11+, type hints на всех публичных функциях.
- Black-совместимое форматирование (двойные кавычки, 4 пробела, длина 100).
- Импорты: stdlib → third-party → local.
- Бизнес-логика — в сервисах. Роуты — тонкие: валидация → сервис → сериализация.
- Модели — `@dataclass`. ORM нет.
- Кастомные исключения — единый базовый класс, коды ошибок строковые (`ERR_MULTI_INTERFACE`).
- Никаких `print()` в коммитах — logger.

### Rust
- Только safe Rust. `unsafe` — с обоснованием в комментарии.
- Публичное API `taptuna._native` — минимальное и стабильное.
- Ошибки наружу — `PyResult` с согласованными типами исключений.
- Тесты — `cargo test` рядом с кодом.
- Никакого `tokio`, асинхронности, сетевых вызовов в v1.

### HTTP API (§15 ТЗ)
- Все эндпоинты — JSON, включая ошибки: `{error: {code, message, details}}`.
- Все долгие операции — jobs + SSE.
- Все пути — внутри каталога проекта.
- Не изобретать новые эндпоинты — сверяться со списком §15.

### CLI (§11.3 ТЗ)
- Команды перечислены в ТЗ. Работают без GUI. После `ingest` — без tshark.
- Никаких «удобных» дополнительных флагов без согласования.

### Frontend (§16, §16.1 ТЗ)
- Vanilla JS. Никаких фреймворков.
- Все запросы — через единую обёртку `api.js`. Прямой `fetch` в других файлах запрещён.
- Никаких inline-обработчиков (`onclick`).
- 9 обязательных экранов из §16.
- UX-требования §16.1 обязательны: unknown/not_applicable визуально отличимы; «предположение» ≠ «факт»; клик по ячейке → байты источника; прогресс+отмена для долгих операций; follow-stream помечен «не источник истины»; virtual scroll для потоков > 1 МиБ; jump-to-offset.

## 8. Тесты

`make test` и `make test-examples` должны быть зелёными перед коммитом.

Обязательное покрытие:
- **Unit:** reassembly (property-based: перестановки, дубли, перекрытия, wraparound), framing (4 стратегии, resync, границы), декодеры (все типы, включая bcd/ipv4/mac), safe-eval (арифметика, предикаты, отказ на disallowed nodes).
- **Integration:** fake-tshark (shell-script) → ingest → sessions/segments/packets. Тест **считает** запуски tshark — ровно один на файл. Sandbox: whitelist, timeout, kill/respawn, stderr flood. Point-lookup в фоне.
- **Cross-validation:** native vs Python — одинаковый `result_hash` на корпусе. Два прогона verify — идентичный `result_hash`.
- **E2E:** `examples/input/*.pcap` (включая дефектные) + `examples/expected/*.json` + `make test-examples`.
- **Краевые случаи §18** — все покрыты тестами, включая политики overlap (×3), checksum, повторный импорт sha256, ошибку одной сессии, wraparound seq.

Фикстуры — синтетические PCAP, генерируются скриптом. Реальные дампы в репозиторий не коммитить.

## 10. Рабочий процесс агента

### Перед началом задачи
1. Прочитать `ТЗ.md` целиком и этот `AGENTS.md`.
2. Проверить, что задача не в Out of scope (§4) и не относится к «возможным расширениям».
3. Если неоднозначно — вопрос **до** начала работы.
4. Если задача требует нарушить инвариант из §5 — стоп и вопрос. Не обсуждается.

### Во время работы
1. Один логический шаг = один коммит.
2. Не трогать файлы вне задачи. Рефакторинг — отдельным коммитом с предупреждением.
3. Не менять стек, схему БД, публичное API Rust-ядра, `requirements.txt` без явного разрешения.
4. Баг в существующем коде — сначала сообщить, не чинить молча.
5. Перед созданием файла — проверить, нет ли подходящего места.
6. Порядок реализации — из §23 ТЗ. Не перескакивать этапы.

### После работы
1. `make test` и `make test-examples`.
2. Ручная проверка UI/CLI, если затронуты.
3. Кратко: что изменено, какие файлы, что проверено.

## 12. Полезные напоминания

- sha256 записи — единственный надёжный идентификатор. Проверяется при открытии проекта.
- Multi-interface / multi-section PCAPNG ловится на инспекции до создания сущностей. Ошибка — `ERR_MULTI_INTERFACE`.
- Point-lookup (`-T json` на один frame) — вне hot-path Flask-worker.
- `stderr` tshark вычитывается всегда, иначе дедлок на 64 КиБ.
- Таймауты и лимиты вывода — настраиваемые, ошибка явная, **без скрытого усечения**.
- Семантика времени: `frame.time_epoch` — время наблюдения в точке захвата. Наследуется всеми производными. Явно фиксируется в UI и отчёте.
- `result_hash` — sha256 канонизированного JSON. Недетерминизм логируется с seed.
- Action Log — сущность первого класса, отдельная таблица, отдельный API. `Observation` может ссылаться на `action_log.id`.
- Проект — каталог (§10 ТЗ). Не упаковывать в один файл, не добавлять код архивации.
- Экспорт — только Markdown / HTML / JSON.
- Термины — только из §3. Новые слова из ТЗ использовать так же, как ТЗ, а не изобретать свои.
- Проверять Definition of Done (§22 ТЗ) перед объявлением этапа завершённым.
