# AGENTS.md

Файл-инструкция для ИИ-агентов (Pi, Claude Code, Cursor и др.), работающих над проектом «Лаборатория протоколов». Читается агентом при старте сессии и определяет правила поведения в этом репозитории.

---

## 1. Что это за проект

Локальное веб-приложение для ручного анализа TCP-трафика из `.pcap/.pcapng`. Пользователь открывает дамп, выбирает TCP-сессию, видит реассемблированный поток в hex-вьювере, размечает границы сообщений, описывает структуру полей декларативным JSON, применяет интерпретацию к корпусу сессий и экспортирует отчёт.

**Один пользователь, один ПК, браузер = GUI.** Всё взаимодействие — через `http://127.0.0.1:5000`. Консоль — только для `python main.py`.

Полное ТЗ лежит в `ТЗ.md`. При любых сомнениях — этот файл источник истины. AGENTS.md — сокращённая выжимка правил.

## 2. Жёсткие границы scope

**НЕ делаем никогда, даже если кажется полезным:**

- Расшифровку TLS, разбор сжатия, IPv6, не-Ethernet канальный уровень.
- Автоматический вывод протокола без человека.
- Автоматическое связывание запрос↔ответ (только ручная разметка + простая эвристика).
- Асинхронность, WebSocket, очереди задач, Celery, Redis. Backend синхронный.
- ORM, базы данных. Состояние — файлы и in-memory.
- Сборщики фронтенда (webpack, vite, node.js). Только vanilla JS + `<script>`.
- Аутентификацию, многопользовательский режим.

Если задача требует чего-то из этого списка — **остановись и спроси пользователя**, не импровизируй.

## 4. Структура проекта (не нарушать)

```
protocol_lab/
├── main.py                  ← единственная точка входа
├── config.py                ← все константы
├── requirements.txt
├── README.md
├── backend/
│   ├── app.py               ← создание Flask, регистрация роутов
│   ├── routes.py            ← ВСЕ HTTP-эндпоинты (только здесь)
│   ├── models/              ← dataclass-модели, без ORM
│   ├── services/            ← вся бизнес-логика
│   └── utils/               ← hex-хелперы, ошибки, проверка tshark
├── frontend/
│   ├── templates/index.html
│   └── static/{css,js}/
├── data/{captures,projects}/
└── tests/{fixtures,test_*.py}
```

**Правила раскладки:**

- Бизнес-логика **только** в `backend/services/`. Роуты в `routes.py` — тонкие обёртки: валидация входа → вызов сервиса → сериализация ответа.
- Модели — `@dataclass`, никаких SQLAlchemy/pydantic.
- Новый сервис = новый файл в `services/`. Не раздувать существующие.
- Логика анализа не должна попадать в `main.py`, `app.py` или фронтенд.
- Каждый фронтенд-экран = отдельный JS-файл по аналогии с `sessions.js`, `stream.js` и т.д.

## 5. Ключевые инварианты (не нарушать никогда)

1. **Все ошибки — в GUI**, а не в консоль. Backend возвращает `{error: {code, message, details}}` с HTTP 4xx/5xx. Фронтенд показывает тост/модалку.
2. **TCP-реассемблинг сортирует по `tcp.seq`, а не по порядку пакетов в файле.** Retransmission с идентичными seq+len+data игнорируется. Overlap — политика «первый победил» (настраивается в `config.py`).
3. **Gaps не скрывать.** Если в потоке пропуск — создать `ByteChunk` с `is_gap=True`. UI обязан показать gap явно.
4. **Интерпретация — декларативный JSON.** Никаких eval, exec, импорта пользовательского кода в основном пути. `rules_python.py` — только как отдельный опциональный режим с явной пометкой «непереносимо».
5. **Ни одно правило не роняет применение.** Если правило выходит за границы или неприменимо — `FieldValue` получает `error="out_of_bounds"` или `not_applicable`. Исключений не бросать.
6. **`.tlproj` переносим между машинами.** Внутри ZIP — только относительные пути. Абсолютные пути (`/home/user/...`) запрещены.
7. **Один capture за раз.** Не пытаться держать состояние нескольких открытых дампов.
8. **Производительность — часть контракта.** 100 МБ pcap / 250k пакетов: открытие ≤ 90 с, применение интерпретации ≤ 10 с. Если правка ломает это — предупредить пользователя.

## 6. Соглашения по коду

### Python

- Python 3.11+. Type hints обязательны на всех публичных функциях и методах.
- Никаких `print()` для отладки в коммитах — использовать логирование или возвращать ошибку наверх.
- Форматирование — `black`-совместимое (двойные кавычки, 4 пробела, длина строки 100).
- Импорты: stdlib → third-party → local, разделены пустой строкой.
- Кастомные исключения — в `backend/utils/errors.py`, наследуются от базового `ProtocolLabError`.
- Все константы — в `config.py`. Магические числа в коде запрещены.

### HTTP API

- Все эндпоинты возвращают JSON. Даже ошибки.
- Пути — как в §4 ТЗ. Не изобретать новые без согласования.
- Метод + путь фиксированы: `GET /api/health`, `POST /api/capture/open`, и т.д.

### Frontend

- Никаких фреймворков. Только `fetch`, DOM API, `addEventListener`.
- Все запросы к backend — через `api.js`. Прямой `fetch` в других файлах запрещён.
- Никаких inline-обработчиков (`onclick="..."`). Только `addEventListener`.
- Состояние экрана хранится в модуле экрана, не в глобалах `window`.

## 7. Тесты

- Каждая новая функция в `services/` требует теста в `tests/`.
- Фикстуры — синтетические pcap, генерируются скриптом (scapy). Реальные дампы в репозиторий не коммитить.
- Обязательный минимум:
  - `test_tcp_reassembly.py` — retransmission, out-of-order, gap.
  - `test_framing.py` — ручная и авто-разметка.
  - `test_interpretation.py` — все типы полей + out_of_bounds + `$length`/`$end-N`.
- Перед коммитом — `pytest` должен быть зелёным.

## 8. Рабочий процесс агента

### Перед началом задачи

1. Прочитать `ТЗ.md` и этот `AGENTS.md`.
2. Проверить, что задача не попадает в §2 (границы scope).
3. Если задача неоднозначна — **задать вопрос до начала работы**, а не после.

### Во время работы

1. Один логический шаг = один коммит с осмысленным сообщением.
2. Не трогать файлы вне задачи. Если нужен рефакторинг — отдельный коммит и предупреждение.
3. Не менять `config.py`, `requirements.txt`, структуру папок без явного разрешения.
4. Если обнаружен баг в существующем коде — сначала сообщить, не чинить молча.

### После работы

1. Запустить `pytest`.
2. Проверить приложение вручную, если менялся UI или эндпоинт.
3. Кратко описать в ответе: что изменено, какие файлы затронуты, что проверено.

## 10. Полезные напоминания

- `tshark` должен быть установлен в системе. При старте `main.py` — проверка, при отсутствии — ошибка в браузере, не в консоль.
- `pyshark.FileCapture` — ленивый итератор, использовать `use_json=True, include_raw=True`. Не грузить весь дамп в память без нужды.
- Hex-вьювер должен уметь: выделение диапазона, копирование hex, поиск по байтам, клик по байту → offset в буфер. Это R2 из критериев приёмки.
- Кнопка «показать пакет-источник» — обязательна (R1).
- Экспорт отчёта генерирует три файла: `report.md`, `interpretation.json`, `apply.py`. `apply.py` должен работать без GUI.
- README обязан содержать раздел «Явные ограничения» — скопировать из §8 ТЗ.
